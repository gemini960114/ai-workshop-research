# 憑證 PDF → record.xlsx

把「核銷憑證黏存單」掃描 PDF 的資料，一張一列填進 `record.xlsx`。
所有指令都用 `uv run`（專案規定，不直接用 `python`／`pip`）。

`SKILL_DIR` = 這個檔案所在的資料夾；`SCRATCH` = 本次 session 的 scratchpad 資料夾（沒有的話用系統暫存資料夾）。

## 流程

1. **找檔案**
   - 使用者指定的 PDF；沒指定就用工作資料夾裡的所有 `*.pdf`。
   - 範本是 `record.example.xlsx`，輸出是 `record.xlsx`（不存在時腳本會從範本建立）。
   - 如果 `record.xlsx` 已有資料，已經登錄過的控帳編號會被腳本跳過，所以重跑不會重複。

2. **轉成圖片**（這些 PDF 是掃描檔，沒有文字層）
   ```bash
   uv run --script "$SKILL_DIR/scripts/render_pdfs.py" --out "$SCRATCH/pages" *.pdf
   ```
   接著用 Read 逐張看 PNG。手寫或印章看不清楚時，用 `--dpi 250` 重新轉，再看一次。

3. **辨識欄位**：照下面的「欄位規則」，每張記下所有值和旗標。

4. **交叉核對**（任何一項對不上 → 該欄標 `uncertain`，note 寫出兩個數字）
   - 發票上的「銷售額＋稅額＝總計」。
   - 發票總計＝黏存單上的「核銷金額」。
   - 核銷金額的國字大寫和阿拉伯數字一致。
   - 買受人統編應為 80778299。

5. **寫入**：把結果寫成 `$SCRATCH/records.json`（格式見 `scripts/append_rows.py` 開頭的說明），然後執行：
   ```bash
   uv run --script "$SKILL_DIR/scripts/append_rows.py" \
     --xlsx record.xlsx --template record.example.xlsx \
     --data "$SCRATCH/records.json" --backup-dir "$SCRATCH/backup"
   ```
   腳本會自動處理這些事：
   - 寫入前先備份。
   - 新資料接在現有資料後面，合計列往下移，並改成 SUM 公式。
   - 項次自動編號，計畫代號用公式 `=MID(B?,9,10)` 從會計科目取出。
   - 依旗標上色、加註解，並確保 K1:L2 有黃／藍底的說明。

6. **回報**：用表格列出每一列的「項次、控帳編號、發票號碼、金額、賣方統編、計畫代號」，並逐一說明黃底和藍底的格子是為什麼。如果使用者說「先做一筆」，就只寫第一張，等使用者確認後再寫其他張。

## 欄位規則

PDF 的上半部是「核銷憑證黏存單」，下半部黏貼發票或收據。

| 欄位 | 從哪裡讀 | 注意 |
|---|---|---|
| 會計科目 | 黏存單「會計科目／科目說明」第一行 | 格式：`03-1111-03114Z1200-0000-51330607-00-00` |
| 控帳編號 | 黏存單左上「控帳編號：」 | 12 位數字 |
| 發票號碼 | 發票左上角「RT 10707602」，要合併成 `RT10707602`；電子發票讀「發票號碼：」 | **免用發票收據沒有號碼** → 值為 `null`，旗標 `missing` |
| 發票金額 | 發票的「總計」（**含稅**，使用者已確認） | 不用標藍；只有交叉核對對不上，或數字看不清楚時才標 `uncertain` |
| 總計金額 | 黏存單的「核銷金額」 | 和發票金額不一樣時，兩欄都標 `uncertain` |
| 發票統編 | **賣方**統編：統一發票專用章上的號碼，或電子發票的「賣方…統一編號」 | 不是買方的 80778299。開頭是 0 的照原樣傳字串 |
| 發票抬頭 | 發票上的買受人 | 通常是「財團法人國家實驗研究院國家高速網路與計算中心」。手寫字看不清楚但明顯是本單位時，填全名即可；若是別的單位，照實填並標 `uncertain` |
| 負債科目 | PDF 上沒有，固定用範本的值 `03-0000-0000000000-0000-21410109-00-00`（使用者已確認） | 傳 `null`，腳本會自動帶入範本的值，不標藍 |
| 項次、計畫代號 | — | 腳本自動產生，不用傳 |

## 旗標原則

- `missing`（黃底）：PDF 裡確實沒有這項資料，值留空。
- `uncertain`（藍底）：有填值，但不是百分之百確定，例如手寫模糊、印章看不清、交叉核對對不上、某欄的定義不確定。
- 藍底只用在「從 PDF 讀出來的值」有疑慮時。已經確認過的欄位規則不要再標藍，否則藍底太多，真正需要核對的地方反而會被淹沒。
- 不要把猜出來的值當成確定值。note 要寫具體原因，讓人看註解就知道要核對什麼。
- 腳本也會自動把格式不符的值（例如統編不是 8 位數）標藍。
- 使用者如果確認某條規則（例如「發票金額就是含稅總計」），之後那個欄位就不用再標藍；最好把這條確認更新到上面的欄位規則裡。
